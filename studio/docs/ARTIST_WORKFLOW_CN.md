# Kiana Studio 美术使用流程

Studio 0.3 默认使用引导模式。先拿到正确画面，再分析画面结构，最后核对资源和用途。

## 1. 获取画面

点击“启动游戏获取画面”，选择绝区零、崩铁、崩坏 3、原神或鸣潮的预设。
预设没有找到程序时，选择实际安装的游戏 EXE；保存目录可以自由选择。
点击“检查设置”可检查路径、运行时和所需兼容功能。旧运行时缺少崩铁/原神兼容开关时，检查会说明需要 Kiana v12。

启动后切回游戏，进入你要研究的场景。工作台显示已连接、截取按钮可用后，点击“截取当前画面”。
在工作台里按 F12 或 PrintScreen 也会触发截取；未连接时不会再打开启动设置。
游戏内快捷键仍由 RenderDoc 处理。

需要切换游戏时，点击“结束捕获会话（游戏继续运行）”。工作台会等待当前帧保存，关闭捕获连接并保留已有文件，不会结束游戏进程。

已有 RDC 时，直接点击“打开已有画面文件（RDC）”。RDC 保存的是一帧绘制数据，不是录像。
五个游戏的详细参数及后端验证限制见 [默认启动参数](../../kiana/GAME_LAUNCH_PRESETS.md)。鸣潮本轮不重新启动测试。

## 2. 确认画面，再分析

先看整帧预览。黑屏、启动标志、下载画面都可能成功保存为 RDC，但不代表抓到了目标场景；需要时重新截取。
点击“分析这张画面”，确认游戏引擎，再点击“开始拆解画面”。
Unity 和 Unreal 与 D3D11/D3D12 是不同概念，工作台不会按图形后端推断引擎。
未知来源需要手动选择；已知游戏预设提供初始选择，用户仍可修正。

默认手动截取、确认后分析。需要自动流程时，可在启动设置的“高级设置”开启自动捕获或自动分析。

## 3. 看懂结果与素材

结果页会显示真实绘制操作、已索引绘制层、已导出几何片段和证据项。
选择某一层，可看用途解释、检查建议和原始判定依据。角色/场景、阴影、天空、透明特效等用途分类属于规则推测。
点击“检查这一层的真实输出和贴图”可进入详细模式，查询 EID 输出、资源与 Shader。
点击“打开分析素材文件夹”打开已经生成的分析包；该按钮不会另行导出完整游戏场景。

需要明确区分：

- **文件记录**：绘制事件、资源绑定、实际导出的几何与图像。
- **自动推测**：绘制层用途、资源用途和角色/场景候选分类。
- **待确认**：原始物体名、完整材质关系、骨骼和动画。单帧数据不等于完整游戏工程。

示例工作区始终标为“示例数据”，需要主动打开；未获取画面时不会用示例图冒充捕获预览。
某个步骤的真实输出导出失败时，详细模式显示失败信息，不会一直停在导出中，也不会用整帧图替代该步骤的输出。

## 出错后怎么办

错误会保留在引导页或启动设置里。已有 RDC 不会因分析失败被删除。
可重试分析、重新选择路径，或点击“打开捕获与日志文件夹”查看保存的文件。
“检查本地运行环境”提供运行时路径与组件状态。使用便携版时，启动 Studio 前设置 `KIANA_HOME` 为 Kiana v12 目录。

Studio 安装/便携包包含自己的 Python 捕获与分析适配脚本（`resources/kiana`），并保留 Python 包目录结构，不需要依赖开发机的源码目录。
RenderDoc Native 运行时仍需单独安装或指定；为崩铁、崩坏 3、原神使用 Kiana v12。
随包使用说明位于 `resources/studio/docs/ARTIST_WORKFLOW_CN.md`，默认游戏参数位于 `resources/kiana/GAME_LAUNCH_PRESETS.md`。

## 开发验证

运行 `npm run typecheck`、`npm run lint`、`npm run test:workflow` 和 `npm run build`。
`test:workflow` 使用 Node 22.6 以上的 TypeScript stripping，验证预设、后端切换、Windows 参数解析、会话就绪条件和引导步骤。
Python 回归为 `python -m unittest kiana.tests.test_studio_capture -v`，包含子进程跟踪、手动触发和启动兼容变量传播。
