# RDC frame to Unity

## Core rule

The captured final output is a **reference**. Never call a full-frame PNG on a quad a reconstruction. Build an editable Unity scene from the draw data and use captured intermediate render targets only as clearly labelled stage evidence or temporary composition layers. Keep any manual approximation visible in the progress report.

Aim first for the captured **art direction** in the editable Unity scene: material separation, light and shadow shapes, face treatment, highlights, rim, outlines and composition. Use pixel differences to locate regressions and verify a stage, not as an instruction to chase zero error while most shader features are absent. For each material family, maintain a feature map with source EID/PS instructions and texture/constant evidence, implementation status and the next visual gate. A G-buffer attachment alone does not identify AO, SDF or specular; follow the sampled value through the actual shader branch before assigning that semantic.

## Stage sequence

1. **Inventory.** Confirm the exact RDC, frame number, API, output size, draw/dispatch counts and pass timeline. Save source paths and capture hash. Enumerate draw EIDs and every texture resource ID. Keep a machine-readable EID → texture slot → resource ID mapping.
2. **Geometry.** Export all relevant IA meshes, including face, hair, eyes, weapon, effects and repeated outline draws. Kiana ASCII FBX may import into Unity as an empty transform; run `scripts/convert_kiana_fbx.py SOURCE.fbx DEST.bytes`, then use `assets/ImportKianaMesh.cs` in the live Unity Editor. Verify vertex and triangle counts. Preserve each draw as its own GameObject and pass group.
3. **Transforms, bones and camera.** Raw IA positions are not necessarily skinned or in a common coordinate space. Compare **every vertex** of each draw with its post-VS output, vertex shader and bound constant buffers before assigning Unity transforms. In the frame 38112 pass, VS `cb1[0..3]` contains per-draw local-to-world columns; `cb0[127..130]` plus clip bias `cb0[21].xy` gives the camera VP. Use `scripts/build_gbuffer5_transforms.py` and `scripts/validate_gbuffer_vertices.py`; a first-vertex match alone is insufficient. Face/head alignment must be checked against the rendered RDC pass. A single RDC frame establishes a pose, not a reusable animation clip.
4. **Materials.** Export the actual bound textures through Kiana IPC with `scripts/export_kiana_ipc_textures.py` or the character batch script. Import each unique texture once, preserve original slot, stage and format in JSON, bind it to the corresponding Unity material, and compare normals, masks, transparency, shadow and tone mapping against the pass evidence. Inspect VS/PS disassembly to identify the sampled UV channel. For exported D3D textures, explicitly validate V orientation in Unity; frame 38112 face atlas requires `float2(u, 1-v)` with the current PNG importer. Vertex-stage textures such as `Eye_E` must not be silently ignored. Bound/exported does not mean sampled/rendered.
5. **Scene and 2D composition.** Reconstruct scene/background and UI draw order from their own events and atlases. Keep 3D passes, postprocessing and UI layers separate. A captured intermediate RT may be used to isolate a stage while native implementation is in progress; label the temporary use.
   For frame 38112, keep the pass-5 scene black while checking G-buffer pixels. `assets/GBufferBlackSkybox.shader` removes Unity's unrelated brown Scene-view sky and ground without changing the camera or mesh. Build final UI backgrounds in a **separate** stage: export their own textures, use `inspect_postvs.py` for their clip positions/UV/vertex color and `scripts/build_ui_postvs_manifest.py` for the six source indices per draw, then run `assets/BuildCapturedUIBackground.cs` in Unity. `assets/CapturedUIBackground.shader` starts from the captured UI pixel shader's premultiplied alpha path. Verify the specific draw's PS constants, mask texture, blend and final RT before calling its appearance exact. Never substitute the complete frame PNG for the UI layers.
6. **Validation.** Export per-EID target snapshots with `scripts/export_gbuffer_snapshots.py`, so a change can be attributed to an exact draw (for example, white eyes at EID 1035 become red at EID 1273). Extract rasterizer, depth/stencil and blend state with `inspect_gbuffer_state.py`, then build a compact per-draw state manifest with `build_gbuffer5_states.py`; a single shared material state is insufficient. Do not enable a tentative D3D→Unity cull/depth mapping just because the enum values were extracted: verify the camera, target orientation and Scene/Game views first, and restore the prior baseline if faces break. Render from Unity at the captured resolution, compare against the RDC final output and relevant stage outputs, record quantitative error and inspect visible misalignments. Finish a stage only when its mesh/binding coverage and visual acceptance gates pass. Update the progress document after every stage.

### Frame 38112 depth and draw order

- A captured camera projection matrix can place RDC depth in Unity clip space with the opposite ordering expected by Unity's default depth test. In frame 38112, correct the captured camera pass by `clip.z = clip.w - clip.z`, retain `ZTest LEqual`, and assign distinct opaque render queues in ascending EID order (`2000 + draw index`). This brought the face EID 992 in front of the prior meshes while retaining real 3D depth.
- Apply the depth correction only while the captured camera renders. `assets/CapturedCameraMatrix.cs` sets `_RdcDepthFlip=1` in `OnPreRender` and resets it to 0 in `OnPostRender`; `assets/CapturedAlbedo.shader` uses this global. A material-wide depth flip breaks the editable Scene view. After changing this logic, capture **both** the Scene view and the captured Game camera and check that `_RdcDepthFlip` returned to 0.
- Keep Kiana/RenderDoc source snapshots and Unity stage renders at the same resolution and orientation. `assets/CaptureGBuffer5Stages.cs` renders specific EID stages without leaving scene GameObjects changed. `scripts/compare_stage_pngs.py` reports foreground IoU and RGB MAE; high IoU alone does not establish 1:1 shading.
- When a free Unity Scene view seems to show a different **whole-body pose**, audit live MeshFilter vertices rather than moving one prop by eye. `assets/AuditCapturedPose.cs` compares each scene Transform's actual world coordinates against per-draw RDC `cb1` matrices and produces an upright view with the same captured VP without mutating the scene. Frame 38112 has max live-world error 0.00006104 across 26 meshes; the upright source/Unity foreground IoU is 0.986129. The Scene camera is a separate editable orbit and the RDC RT may be vertically inverted; do not rewrite a source-aligned pose to compensate for an unmatched view. A single captured frame does not recover rig animation.
- Export disassembly for each unique pixel shader with `scripts/inspect_gbuffer_shaders.py`, then cross-check static texture references and the per-EID binding manifest using `scripts/analyze_shader_texture_slots.py`. Distinguish `t1` structured buffers from image textures. A texture assigned to a Unity material property is only **bound**; mark it implemented only after the Unity shader samples it and its visual contribution is checked.
- Export pixel-stage constant buffers for every draw using `scripts/inspect_pixel_cbuffers.py` in Kiana's bundled replay Python, then use `scripts/build_gbuffer5_pixel_constants.py` to pair only directly referenced registers with each shader's disassembly. Verify the source albedo multiplier before adjusting Unity tint: frame 38112 EID 945 and EID 992 both use `(1,1,1)`, so their large color error must be pursued in the remaining sampled textures, lighting and output composition.
- Dynamic constant-buffer indexing needs a separate table extraction. PS 31475 reads `cb3[band+5/10/15]` after choosing a band from `t5.r`; `scripts/extract_material_tables.py` exports all five band rows per draw. Frame 38112's six PS 31475 draws have four distinct tables. Do not reuse EID 858's texture-array slice numbers for EID 945. Gate an individual material branch with source-vs-Unity stage MAE and keep it off if it worsens output, even when its sampled slots are correct.
- For material-array/matcap branches, preserve **operation order and blend mode** from the PS, not just the correct texture and slice. Applying the layer before lighting caused severe EID912/945 regressions. Use adjacent source RT snapshots to mask each draw's actual changed pixels; in this frame EID875 umbrella benefited from the corrected t7 path while EID895 hair was neutral and EID912/945 regressed.

## Live tools

### Fixed DXBC → HLSL workflow

When a captured D3D11/D3D12 pass must be reproduced rather than approximated, use the checked-in batch workflow in [references/dxbc-to-hlsl.md](references/dxbc-to-hlsl.md). Run `scripts/export_decompile_shaders.ps1` so one replay process exports both VS and PS bytecode for every requested EID, then decompiles the resulting DXBC containers with the pinned `d3dasm` tool. Do not recreate this tool chain ad hoc.

Treat decompiled HLSL as a semantics-preserving translation aid, not recovered authoring source. Preserve the raw DXBC, shader resource ID, EID, stage, hashes, constant buffers, resource slots, samplers, blend/depth/stencil state and output formats beside the HLSL. A Unity port is complete only after the native Unity output passes same-EID A/B validation; a captured render target may be an offline oracle but must never be wired into the runtime result.

- Use the connected Unity CLI/Pipeline to refresh assets, create Mesh `.asset` files, modify the scene and capture Game view. Avoid hand-editing `.unity` or `.asset` YAML.
- Kiana's Python MCP client communicates with a live bridge using a mailbox. `scripts/export_kiana_ipc_textures.py` discovers a bridge with the requested frame and exports resource IDs; `scripts/export_character_stage.py` exports all 26 frame 38112 character draws and texture mapping. The installed `renderdoc.pyd` is coupled to its embedded Python ABI; do not import it into an arbitrary external Python version.
- For direct RenderDoc APIs, invoke Kiana's bundled `kiana_qrenderdoc.exe --python=SCRIPT` in a separate replay process. `inspect_postvs.py` and `inspect_gbuffer_shaders.py` use this path. `PipeState.GetConstantBlocks(stage, onlyUsed)` returns descriptors; read `.descriptor.resource`, `.byteOffset`, `.byteSize` and then `ReplayController.GetBufferData`. `DisassembleShader` takes a `ResourceId` as its first argument, not the PipeState object.
- Store generated source assets and evidence separately from Unity `Library`. The Unity project may live outside this repository; commit the reusable scripts, shaders, importers and documentation here.
